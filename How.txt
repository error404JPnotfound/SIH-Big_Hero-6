# How the CareConnect Symptom Checker Works (Workflow Overview)

The Symptom Checker is a fast, deterministic, rule-based system designed to evaluate patient symptoms and flag medical emergencies. It strictly avoids using AI or LLMs to ensure that the results are 100% predictable, safe, and computationally inexpensive.

Here is the step-by-step workflow of how the system operates:

## 1. Auto-Suggestions (User Input Phase)
- When a patient clicks the symptom text box and starts typing, an auto-suggestion dropdown appears.
- On mobile devices, these suggestions intelligently appear directly above the phone's native keyboard as auto-complete chips.
- Where do they come from? The suggestions are powered by a native HTML5 `<datalist>` element embedded in the React UI (`SymptomTriage.jsx`). The list is populated with exact-match keywords across English, Hindi, and Gujarati. 
- To keep the UI clean, the suggestions are hidden when the text box is empty and only appear after the user types at least one character.

## 2. Multilingual Translation & Normalization (Backend Processing Phase)
- When the user submits a symptom (e.g., "છાતીમાં દુખાવો" or "सीने में दर्द"), the React frontend sends this exact string to the FastAPI backend.
- The backend passes the string to the `SymptomNormalizer`.
- How translation works: The normalizer relies on a static dictionary file (`seed/translations.json`). This file acts as a translation map. It looks up the exact Hindi or Gujarati phrase and maps it to a standard internal English code. 
- Example: "છાતીમાં દુખાવો" (Gujarati) -> mapped to internal code: `severe_chest_pain`.

## 3. Evaluation (Triage Engine Phase)
- Once the symptom is normalized into an internal code (like `severe_chest_pain`), it is passed to the `TriageEngine`.
- How evaluation works: The engine checks the code against a local database file (`seed/symptoms.json`), which contains medical rules and flags defined by healthcare professionals.
- If the internal code has the property `"red_flag": true` attached to it, the engine immediately categorizes the symptom as an EMERGENCY.
- If it doesn't match a red flag, or if the system doesn't recognize the exact string, it defaults to a safe `NON_URGENT` status. 
- Because this is rule-based, it only flags an emergency if it finds an exact, predefined match.

## 4. Response & UI Update (Final Phase)
- The backend constructs a response containing the triage level (`EMERGENCY` or `NON_URGENT`) and recommended actions (e.g., "Seek emergency medical care immediately").
- The React frontend receives this response and instantly updates the UI.
- If it is an emergency, the UI actively triggers a pulsating red "EMERGENCY SIGNAL ACTIVE" banner to immediately alert the patient and nearby staff.
